# 拼多多下单与先用后付试用版（0.2.0-pdd）

基于 jinyule/bookkeeping，基线提交 e09c8eae9be239d647c49c1d1b851ef24cd792ff。
这是个人试用改版，尚未在 OPPO PKB110 真机验证；图片不能证明页面文字节点可被读取。

## 下单流程

- 开启通知使用权、无障碍识别，以及“自动”页中的拼多多来源。
- 只浏览提交页不会入账。读取到拼多多提交按钮的真实点击事件时，创建待确认记录；点击本身不等于下单成功。
- 先用后付页面：从“确认收货后付款 ¥3.99”取应付金额，而不是“0元下单”的 0，也不是商品划线价。
- 多多支付页面：从“提交订单 ¥3.99”取应付金额，区分为多多支付，不能把它当成负债。
- 明确的先用后付下单成功页或成功通知也可生成待确认记录。金额有歧义时不猜测。
- 开启发送通知权限后可收到待确认提醒，点通知进入订单页。未授权提醒时记录仍在首页“先用后付”入口内。
- 核对商品、分类、金额、支付方式和实际下单日期，确认后计入下单日支出。默认识别时间是检测时间，旧订单务必改日期。
- 读不到按钮文字或金额时不会截图或自动点击，可使用“补记先用后付订单”。

## 实际扣款

- 确认的先用后付订单显示待扣款余额；多多支付不计入这项负债余额。
- 明确的拼多多先用后付/多多支付扣款文案归入“待核对扣款”，不重复计支出。
- 只有订单号、金额、时间匹配，且订单唯一时才自动结清。只有金额相同不会自动关联。
- 没有足够证据时在订单中选择“关联已扣款账单”。列表仅提供下单后、同金额的未关联支出或扣款候选，用户须核对确为同一笔。
- 普通微信、支付宝通知没写拼多多或先用后付时，可能仍按普通支出入账。应手动关联该账单，关联后它不再算第二笔支出。
- 未登记过消费的待核对扣款，可选择“作为普通支出”；请先确认没有订单消费，避免重复。
- 已扣款但没有扣款账单时可手动标记结清。以后收到扣款账单时先撤销结清再关联。
- 关联和撤销结清可逆；整单取消删除原消费并保留取消状态。结清订单不能直接整单取消，退款请按实际退款核对处理。
- 部分退款、拆单、分次扣款、不同金额扣款暂不自动关联；请调整实际订单消费金额并核对，或用手动记录处理。不要拿整单取消代替部分退款。

## 升级与数据

包名维持 com.github.bookkeeping，versionCode 从 5 提升到 6，沿用此前试用包的签名。直接覆盖安装，不要卸载旧版。
数据库从 v2 迁移至 v3，仅增加订单表，原账单保留；取消破坏性迁移回退。迁移有实际数据库回归测试。
原版没有完整的数据库导出功能；重要账单请另行留存。覆盖升级不等于已有真机数据已备份。

## 隐私与边界

无 INTERNET 权限，无录屏、截图或云端识别。只处理白名单应用的页面事件。
提交前页面可能有收货信息，订单表不保存整页原文或收货地址，只保存商品、金额、订单号、支付方式和事件类型；短暂缓存的提交信息也只保留这些必要文字。
无障碍的页面文字、按钮点击事件可能被支付应用或系统限制，ColorOS 后台管理也会影响识别。未宣称覆盖所有真实支付场景。

## 构建与测试

JDK 17、Android SDK 36，使用仓库的 Gradle wrapper：

```sh
./gradlew :app:testDebugUnitTest :app:assembleDebug --no-daemon --max-workers=2
```

单元测试包括：提交前不入账、点击按钮提取实际金额、区分两种支付方式、忽略提醒、订单去重；Robolectric + Room 数据库测试覆盖确认入账、结清、撤销、取消、金额不匹配拒绝、扣款早于确认，以及 v2 旧账单迁移。
测试框架下载依赖时需要网络，安装后的 App 不需要联网。
